# tauri-shell TypeScript bindings

Auto-generated TypeScript type definitions for every struct that crosses the
Tauri IPC boundary. Generated by [`ts-rs`](https://crates.io/crates/ts-rs)
from `#[derive(ts_rs::TS)]` annotations in the Rust source.

## Regenerating

The bindings are produced by running the export test under the `bindings`
Cargo feature:

```bash
cd tauri-shell
cargo test --features bindings --test bindings_export
```

That command:

1. Compiles `tauri-shell` with the optional `ts-rs` dependency enabled.
2. Runs `tests/bindings_export.rs`, which forces every annotated type to
   call `ExportType::export_all()`.
3. Writes one `.ts` file per type into this directory.
4. The build script `scripts/build_bindings.sh` concatenates them into
   `index.ts` with a re-export footer for ergonomic consumption.

`cargo check` (without `--features bindings`) is unaffected — `ts-rs` is
an optional dependency.

## Consuming from a TypeScript frontend

These files are plain `.d.ts`-style declarations with `export type`
statements, so they work directly in any TypeScript or `tsc` toolchain.

The recommended npm-side consumption pattern:

1. Symlink (or `npm link`) this directory into your frontend project, e.g.
   `frontend/src/bindings/`.
2. Import individual types by name:

   ```ts
   import type { ProcessOutputEvent, BackendService } from "./bindings";
   import { invoke } from "@tauri-apps/api/core";

   const services = await invoke<BackendService[]>("list_backend_services");
   ```

3. Or alias the whole bundle:

   ```ts
   import type * as Shell from "./bindings";
   ```

For monorepo setups, add this directory as a workspace package
(`"@tauri-shell/bindings": "file:../tauri-shell/bindings"` in
`package.json`).

## What's exported

Every struct or enum that the Rust shell sends or receives over IPC,
plus every event payload, plus every piece of managed state that surfaces
to the renderer. See `index.ts` for the full surface, or grep the Rust
sources for `#[cfg_attr(feature = "bindings", derive(ts_rs::TS))]`.

Concrete categories:

- **State** (`state.rs`): `LogEntry`, `InstallationSnapshot`,
  `InstallationProgress`.
- **Events** (`events.rs`): `ProcessOutputEvent`, `InstallProgressEvent`,
  `BackendUrlEvent`, `JupyterStatusEvent`, `NavigateEvent`.
- **IPC payloads** (`ipc/*.rs`): `BackendService`, `CondaEnvironment`,
  `Extension`, `ExecResult`, `JupyterStatus`, `McpSpec`, `McpStatus`,
  `ServerSpec`, `ServerStatus`, `RouteInfo`, `ProviderSummary`,
  `RoutineMetadata`, plus every `*Args` struct.
- **Error type** (`ipc/mod.rs`): `IpcError` (tagged union).

## Stability

Type names are stable; field renames will appear here automatically the
next time the export test runs. Always re-run the test after touching any
Rust struct that crosses the IPC boundary.
