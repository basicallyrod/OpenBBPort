# Port: Invoke Command Mapping (Tauri → TS)

> Single-sheet checklist of every Tauri command and event in the current
> desktop implementation, mapped to its TypeScript-port equivalent. The port
> team uses this as the IPC surface checklist. **57 registered commands, 8
> events (6 live + 2 dead).**
>
> Generated 2026-05-15. Sources: `raw-deep-dives/ipc-bridge.md`,
> `ipc-bridge.v2.md`, and the IPC contract tables in every `20-features/`
> doc.

---

## Conventions

- **Casing.** Tauri 2.x auto-converts JS camelCase ↔ Rust snake_case via a
  `serde_json` `rename_all = "camelCase"` pass generated by the
  `#[tauri::command]` macro. JS callers in `src/` use both conventions; both
  work. **Port recommendation:** keep snake_case on disk
  (`user_settings.json`, `system_settings.json`, `backends.json` — to match
  the Python `openbb-core` reader), use **camelCase on the wire**, and snake
  in stored JSON. Implement a one-line case-conversion middleware around
  `ipcMain.handle` so existing renderer call sites continue to work.
- **Error returns.** Universal convention today is `Result<T, String>` —
  every error becomes a stringified message in a rejected promise. There is
  no error code, no error class, no typed envelope. **Port recommendation:**
  introduce a typed envelope (Zod-validated):
  `{ ok: true, data: T } | { ok: false, code: string, message: string, detail?: unknown }`.
  Renderer can keep using `await invoke(...)` with a thin `unwrap()` helper.
- **Long-running calls.** Three patterns coexist today (see `ipc-bridge.v2.md §M`):
  - **Pattern A — await + listen.** Most common. Frontend sets up
    `listen("process-output", …)` BEFORE invoking; awaits invoke to
    completion; filters streamed events by `processId`. Example: env
    creation.
  - **Pattern B — fire + poll status.** Used by `install_conda` +
    `setup_python_environment`. The await + a 2s polling effect read
    `get_installation_status` in parallel with `install-progress` event push.
  - **Pattern C — fire-and-forget.** Nine sites discard the promise (e.g.
    `register_process_monitoring` pre-registers, `update_backend_service`
    status writes). Anti-pattern; refactor or accept the laxness.
  - **Pattern D — await without listen (CRUD).** Boring synchronous
    request/response.
  - **Pattern E — listen-only (no invoke).** Listen for a previously-spawned
    process; auto-start case. Requires the main process to retain state
    across renderer page reloads.

  **Port should standardize on Pattern A** for long-running work (await +
  listen via WS / `webContents.send`). Drop polling entirely (Pattern B
  becomes redundant). Pattern C is admissible only for log-buffer
  pre-registers — use Promise.allSettled and never silently discard.

### Silent argument drops (Tauri `serde_json` ignores unknown fields)

| Command | JS sends | Rust accepts | Port fix |
|---|---|---|---|
| `install_conda` | `directory`, `userDataDir` | `directory` only | Add `userDataDir` to signature OR remove from JS payload (installation-progress.tsx:938-941). |

Port-time: **enforce strict input validation** (Zod `.strict()` on every
schema) so unknown fields produce a typed error, not a silent drop.

### Cross-window navigation via `window.eval(…)`

5 injection points to replace with `webContents.send('navigate', …)`:

- `main.rs:408` — `navigate_to_page` body (tray menu nav).
- `main.rs:676` — Tray "Uninstall" item (bypasses the first-load-done gate).
- `main.rs:784` — Setup hook `localStorage.clear()`.
- `main.rs:785` — Setup hook `/setup` redirect.
- `main.rs:799` — Setup hook setting `environments-first-load-done = 'true'`.

Replace with renderer-side `router.navigate(path)` listener and a typed
`{ type: 'navigate', target } | { type: 'localStorage', op, key, value }`
contract. Set the `environments-first-load-done` gate from the React
post-install success callback OR from a dedicated event from the
`update_openbb_settings` handler — do NOT rely on `eval` for it.

### Two `InstallationState` types (collision risk)

- Type A in `main.rs:67-70` — `{ is_installed, installation_directory }`;
  boot snapshot; read by `get_installation_state`.
- Type B in `startup.rs:18-25` — `{ is_downloading, is_installing,
  is_configuring, is_complete, message }`; mutable; read by
  `get_installation_status`.

Port rename: **Type A → `InstallSnapshot`**, **Type B →
`InstallProgressTracker`** (or `InstallPhase`). The two commands sit
adjacent in `generate_handler!` (main.rs:508-509) and are trivially confused
by a maintainer.

### Process-output payload-schema drift

Three emitters use three subtly different shapes:

- jupyter.rs: `{ processId, output, timestamp }`
- backends.rs: `{ processId, output, timestamp, type }`
- environments.rs: `{ processId, output }` (no timestamp, no type)

Port: **normalize to one schema** (`{ processId, output, timestamp,
type: "stdout"|"stderr"|"system" }`) at the emit site. Clients shouldn't have
to special-case the source.

## Port-time additions (commands NOT in current impl)

If the port adopts:

- **Per-command Zod validation.** Wrap `ipcMain.handle` with a generic
  `validateCommandInput<TInput, TOutput>(schema, handler)` so every command
  gets schema-checked args and typed errors. Today this exists only for
  backend commands (the `command_sanitizer.rs` no-whitespace check).
- **Unified cancellation.** Every long-running command takes an `AbortSignal`
  (per-command `AbortController` registered in a Map<correlationId,
  controller>). Replaces today's ad-hoc `abort_installation` / process-kill
  primitives. Use `tree-kill` on Windows.
- **Typed error envelope.** Replace `Result<T, String>` with
  `{ ok, code, message, detail }`. Renderer wraps `invoke` with a tiny
  `unwrap()` that throws an `IpcError` on `!ok`.
- **Health-check / metrics.** A `/health` IPC channel returning
  `{ runningProcesses: [...], logBufferSize, lastInstallPhase, openWindows
  }` for debugging. Today there is no health surface.
- **Correlation IDs for streamed events.** Today `processId` is the de-facto
  correlation key; promote it to a top-level envelope field so log-streaming,
  install-progress, and uninstall-progress all use the same plumbing.

## TS port command surface (recommended shape)

Sketch for an Electron port with typed IPC contracts. The shape mirrors
trpc-electron / electron-trpc; can also be plain `ipcMain.handle` with the
types as ambient declarations.

```ts
// Shared types
export interface IpcEnvelope<T> { ok: true; data: T }
export interface IpcError { ok: false; code: string; message: string; detail?: unknown }
export type IpcResult<T> = IpcEnvelope<T> | IpcError;

export interface InstallSnapshot {     // Type A
  isInstalled: boolean;
  installationDirectory: string | null;
}

export interface InstallProgressTracker { // Type B
  phase: 'idle' | 'download' | 'install' | 'config' | 'complete' | 'error' | 'abort';
  isDownloading: boolean;
  isInstalling: boolean;
  isConfiguring: boolean;
  isComplete: boolean;
  message: string;
}

export interface ProcessOutput {
  processId: string;
  output: string;
  timestamp: number;
  type: 'stdout' | 'stderr' | 'system';
}

// Installation
type InstallationContract = {
  'install:snapshot': () => Promise<IpcResult<InstallSnapshot>>;
  'install:progress': () => Promise<IpcResult<InstallProgressTracker>>;
  'install:prepare-directory': (args: { directory: string; userDataDirectory: string })
    => Promise<IpcResult<boolean>>;
  'install:conda': (args: { directory: string; userDataDir: string }, signal: AbortSignal)
    => Promise<IpcResult<boolean>>; // streams 'install-progress'
  'install:python-env': (args: { directory: string; pythonVersion: string }, signal: AbortSignal)
    => Promise<IpcResult<boolean>>;
  'install:abort': () => Promise<IpcResult<void>>;
  'install:extensions': (args: { extensions: string[]; environment: string; directory: string })
    => Promise<IpcResult<boolean>>;
  'install:openbb-settings': (args: { condaDir: string; environment: string })
    => Promise<IpcResult<void>>;
  'install:default-backends': () => Promise<IpcResult<void>>;
};

// Environments
type EnvironmentsContract = {
  'env:list': (args: { directory?: string }) => Promise<IpcResult<CondaEnvironment[]>>;
  'env:create': (args: { name: string; pythonVersion: string; extensions: string[];
                         directory: string; processId: string }, signal: AbortSignal)
    => Promise<IpcResult<boolean>>;
  'env:create-from-requirements': (args: { name: string; filePath: string;
                                           directory: string; processId: string }, signal: AbortSignal)
    => Promise<IpcResult<boolean>>;
  'env:remove': (args: { name: string }) => Promise<IpcResult<boolean>>;
  'env:update': (args: { environment: string; directory: string }) => Promise<IpcResult<boolean>>;
  'env:get-extensions': (args: { name: string }) => Promise<IpcResult<{ extensions: Extension[] }>>;
  'env:update-extension': (args: { package: string; environment: string; directory: string })
    => Promise<IpcResult<boolean>>;
  'env:remove-extension': (args: { package: string; environment: string; directory: string })
    => Promise<IpcResult<boolean>>;
  'env:exec': (args: { command: string; environment: string; directory: string })
    => Promise<IpcResult<{ stdout: string; stderr: string; success: boolean }>>;
  'env:select-requirements-file': () => Promise<IpcResult<string>>;
  'env:save-working-dir': (args: { path: string }) => Promise<IpcResult<boolean>>;
  'env:get-working-dir': (args: { defaultDir: string }) => Promise<IpcResult<string>>;
};

// Backends
type BackendsContract = {
  'backend:list': () => Promise<IpcResult<BackendService[]>>;
  'backend:upsert': (args: { backend: BackendService }) => Promise<IpcResult<BackendService>>;
  'backend:delete': (args: { id: string }) => Promise<IpcResult<void>>;
  'backend:start': (args: { id: string }) => Promise<IpcResult<BackendService>>;
  'backend:stop': (args: { id: string }) => Promise<IpcResult<void>>;
  'backend:open-logs': (args: { id: string }) => Promise<IpcResult<void>>;
  'backend:generate-cert': (args: GenerateCertArgs) => Promise<IpcResult<CertResult>>;
};

// API Keys (credentials)
type CredentialsContract = {
  'credentials:read': () => Promise<IpcResult<UserSettings>>;
  'credentials:update': (args: { credentials: Record<string, string> })
    => Promise<IpcResult<boolean>>;
  'credentials:open-file': (args: { fileName: 'user_settings.json' | '.env' | '.condarc'
                                              | 'mcp_settings.json' | 'system_settings.json' })
    => Promise<IpcResult<boolean>>;
};

// Logs / process monitoring (shared)
type LogsContract = {
  'logs:register': (args: { processId: string }) => Promise<IpcResult<boolean>>;
  'logs:history': (args: { processId: string; count?: number })
    => Promise<IpcResult<LogEntry[]>>;
  'logs:clear': (args: { processId: string }) => Promise<IpcResult<boolean>>;
};

// Jupyter
type JupyterContract = {
  'jupyter:start': (args: { environment: string; directory: string; working: string })
    => Promise<IpcResult<{ url: string; alreadyRunning: boolean; status: string; processId?: string }>>;
  'jupyter:stop': (args: { environment: string }) => Promise<IpcResult<boolean>>;
  'jupyter:status': (args: { environment: string })
    => Promise<IpcResult<{ running: boolean; url?: string; status: string; processId?: string }>>;
  'jupyter:open-logs': (args: { environment: string }) => Promise<IpcResult<void>>;
};

// Window / app
type AppContract = {
  'app:quit': () => Promise<IpcResult<void>>;
  'app:open-url': (args: { url: string; title?: string }) => Promise<IpcResult<void>>;
  'app:select-directory': (args: { prompt?: string }) => Promise<IpcResult<string>>;
  'app:select-file': (args: { filter?: string }) => Promise<IpcResult<string>>;
  'app:home-dir': () => Promise<IpcResult<string>>;
  'app:install-dir': () => Promise<IpcResult<string>>;
  'app:userdata-dir': () => Promise<IpcResult<string>>;
  'app:settings-dir': () => Promise<IpcResult<string>>;
  'app:check-file': (args: { path: string }) => Promise<IpcResult<boolean>>;
  'app:check-dir': (args: { path: string }) => Promise<IpcResult<boolean>>;
};

// Uninstall
type UninstallContract = {
  'uninstall:run': (args: { removeUserData: boolean; removeSettings: boolean })
    => Promise<IpcResult<void>>;
};

// Full contract
export type IpcContract =
  & InstallationContract & EnvironmentsContract & BackendsContract
  & CredentialsContract  & LogsContract         & JupyterContract
  & AppContract          & UninstallContract;

// Events (one-way, main → renderer)
export interface EventMap {
  'process-output': ProcessOutput;
  'install-progress': { step: string; progress: number; message: string };
  'installation-directory': string;
  'jupyter-status-update': { environmentName: string; status: string };
  'backend-url-discovered': { id: string; url: string };
  'uninstall_progress': string;
}
```

Renaming summary:
- `*_to_directory`, `*_directory`, etc. → consistent `:dir` suffix.
- `_state` vs `_status` collapsed via `:snapshot` / `:progress` distinction.
- `update_*` + `create_*` for backends collapsed into `:upsert`.
- All return types wrapped in `IpcResult<T>` for typed errors.
- All long-running commands take an `AbortSignal` (cancellation primitive).
